# Tangerine

**An independent creative practice.**

Tangerine is a working home for client projects and creative collaborations. It's where work is developed, organized, refined, and brought to completion—not a separate consumer app or a new product to manage.

The practice can take different forms from project to project. What stays consistent is attention to the work: strong ideas, clear communication, considered design, and care for the finished result.

## What this repository is for

This GitHub repository holds technical work, reusable materials, design studies, and the history of earlier Tangerine experiments. **It is not a client portal or a place to publish private client records.** Specific client projects belong here only when their scope and publication permissions are clear.

### Current creative direction

[Identity studies](IDENTITY.md) explore Tangerine's own graphic language. **Industrial Study 004** is the preferred typographic exploration for further development, not a finalized wordmark. The visual system favors clear typography, cyber-white space, graphite, tangerine orange, strong composition, and restraint.

### Historical experiments

This repository originated as a set of experiments under the names Haven and Tangerine. Older files and branches remain deliberately preserved, including:

- [Synthesis interface exploration](SYNTHESIS.md) — **historical concept**, not the current definition of Tangerine.
- [Personal instrument exploration](INSTRUMENT.md) and TABLET studies — earlier interface investigations.
- [Home-system product brief](PRODUCT.md) and [design audit](DESIGN.md) — legacy Haven work.
- Existing HTML/JavaScript prototypes, archived notes, and study branches.

Those studies may contain useful ideas, but they should **not** be mistaken for Tangerine's current purpose or automatically deployed as its website.

## Working principles

- Make the work good before making noise about it.
- Preserve original artwork, writing, photographs, and source files.
- Keep client-confidential material, unreleased concepts, access tokens, and personal data out of this **public** repository.
- Use focused branches and review changes before merging or deploying.
- Keep experiments clearly labeled; don't present studies as finished or approved work.
- Prefer a coherent, useful working environment over additional process or organizational overhead.
